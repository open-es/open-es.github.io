OpenES написано на C++20 з wxWidgets. Платформа збирається MSVC на Windows, GCC на Linux і
Clang на macOS, а CI запускає тести на всіх трьох. Повний опис —
в [ARCHITECTURE.md](https://github.com/open-enterprise-solutions/enterprise/blob/develop/docs/ARCHITECTURE.md).

## Програми і бібліотеки

```
   appstudio      appworkspace                   browser
        │               │                           │
        └───────┬───────┘                           ▼
                ▼                               webserver
            frmclient   (draws the forms)           │
                │                                   │
                │◄──── client protocol ────────────►│
                ▼                                   ▼
   fileserver (a file base,          appcluster ─► appserver, one or more per base
   in the client's own process)                     │
                │                                   │
                └──────────────┬────────────────────┘
                               ▼
               frmserver   (the forms, on the server)
                               ▼
                backend    (the engine, no UI)
                               │
              Firebird · PostgreSQL · ODBC · SQLite
```

| Частина | Що робить |
|---|---|
| **backend** | Рушій: метадані, компілятор та інтерпретатор байткоду, рушій запитів і компонувальник звітів, сеанси, блокування, завдання, шар бази даних, сервер налагоджувача. Інтерфейсу користувача не має |
| **frmserver** | Форми та їхні елементи, що живуть поруч із рушієм; а також інструменти асистента (MCP) |
| **frmclient** | Основа Application Studio та Application Workspace: малює те, що кажуть форми сервера, і відправляє назад дії людини. Прикладного коду не виконує |
| **deskgui** | Інтерфейс користувача настільних програм: елементи й діалоги, які платформа малює сама, світлий і темний вигляд |
| **core** | Основа кожної бібліотеки: рядки, числа, дати, серіалізація, текст запиту, мережа і TLS, картинки (PNG і SVG) |
| Програми | Кожна вибирає, як дістатися до бази, і далі передає роботу бібліотекам. `launcher` і `coderunner` працюють безпосередньо на рушії |

## Усередині рушія

| Підсистема | Що робить |
|---|---|
| **Метадані** | Зберігають застосунок як дерево об'єктів. Оновлення бази даних порівнює його з базою і змінює таблиці за різницею, спершу показуючи точний DDL |
| **Компілятор** | Лексер, парсер, байткод (82 коди операцій), інтерпретатор, LINQ. Скомпільовані модулі кешуються для кожної версії застосунку |
| **Рушій запитів** | Розбирає мову запитів, перетворює її на діалект бази даних або виконує запит у пам'яті, коли SQL не може його виразити |
| **Компонувальник** | Перетворює налаштування звіту на запит, а його результат — на табличний документ |
| **Сеанси** | По одному на користувача, завдання чи службу. Сеанс тримає своє з'єднання, свій код, що виконується, і свої вікна |
| **Блокування** | Блокування записів, спільні для процесів, щоб два сервери на одній базі не перезаписували дані один одного |
| **Завдання** | Регламентні та фонові завдання; завдання виконується один раз на всі сервери, що спільно використовують базу |
| **Шар бази даних** | Єдиний інтерфейс над Firebird, PostgreSQL, ODBC і SQLite; кожен оператор готується заздалегідь, а не склеюється з рядків |
| **Налагоджувач** | Сервер у запущеному процесі, на порту 7700-7709 цього комп'ютера; Application Studio підключається до нього |
| **Сервер MCP** | Доступ асистента до Application Studio та Application Workspace: близько 140 інструментів на порту власного комп'ютера людини, захист токеном, кожен виклик записується до журналу |

## Процеси і бази

Програма, що відкриває файлову базу, тримає одну цю базу. Сервер застосунків теж тримає одну базу,
а кластер запускає один або кілька таких серверів на базу, тож збій у процесі однієї бази не зачіпає
інших. Кожна база має власний пул з'єднань, сеанси, блокування, завдання і журнал, а потік
завжди працює на конкретну базу: глобальної «поточної» бази немає.

## Бази даних

| База даних | Роль |
|---|---|
| **Firebird 5** | За замовчуванням. Вбудована в пакети: файловій базі сервер не потрібен |
| **PostgreSQL** | Промислова експлуатація з кількома користувачами |
| **ODBC** | Шлях до інших баз даних |
| **SQLite** | Тести і журналювання |
