Каждая запись называет симптом, его причину и что делать.

## Запуск программ

**Windows: SmartScreen сообщает «Система Windows защитила ваш компьютер».**
Программы не подписаны цифровой подписью. Нажмите **Подробнее → Выполнить в любом случае**.

**macOS: приложение «повреждено, и его не удаётся открыть» или «не удаётся проверить на наличие вредоносного
ПО».**
macOS помещает в карантин каждый файл загрузки с подписью ad hoc. Выполните один раз:
`find /Applications/OES -exec xattr -d com.apple.quarantine {} \; 2>/dev/null`.
Правый щелчок → «Открыть» снимает карантин только с одного приложения.

**macOS: `launcher` открывается, но Application Studio или Application Workspace не запускается.**
Одно из приложений перенесено из папки `OES`. Они запускают друг друга как соседей, поэтому держите
папку целиком.

**Linux: `error while loading shared libraries: libgtk-3.so.0`.**
Установите GTK 3: `sudo apt install libgtk-3-0`. Для базы PostgreSQL также нужен `libpq5`.

**Файловая база не открывается.**
Держите папку `_fb` рядом с программами: в ней движок Firebird 5, с которым поставляются пакеты.
Системный Firebird его не заменяет. В Ubuntu 22.04 и Debian 12 поставляется Firebird 3, который
не может открыть эти базы.

## Работа с базой

**`appworkspace` открывает пустое приложение.**
Приложение базы пустое. Сначала соберите его в Application Studio и нажмите **Обновить базу данных**.

**Сервер приложений отказывает в базе, или Application Studio отказывает в базе, которую
обслуживает сервер.**
Базу используют либо серверы приложений, либо программы, открывающие её как файловую базу
(`appstudio`, `appworkspace`), но никогда и те и другие сразу. Закройте одну сторону или подключитесь к базе
через сервер: `--address=oes://<host>/<base>`.

**Обновление базы данных ждёт или отклоняется.**
Изменению, которое перестраивает хранимые данные, база нужна в монопольное пользование. Закройте `appworkspace` и все
остальные сеансы этой базы, затем обновите снова.

**Открыты два экземпляра Application Studio, и ассистент редактирует не тот.**
Один адрес и порт ведут к одному экземпляру: тому, который первым начал слушать. Задайте каждому
экземпляру свой порт в **Сервис → Параметры… → Доступ ассистента (MCP)**.

## Сборка

**`'cmake'` или `'msbuild'` не является внутренней или внешней командой.**
Используйте командную строку Visual Studio: «x64 Native Tools Command Prompt for VS 2022» для
пресетов CMake или «Developer Command Prompt» для `msbuild`.

**`wx/wx.h: No such file or directory`, или CMake не находит wxWidgets.**
Нет подмодулей. Выполните `git submodule update --init --recursive`. Повторяйте это после
каждого `git pull`: он может принести новый подмодуль.

**`enterprise.sln`: `LNK1104: cannot open file 'wxbase33u….lib'`.**
Решение подключает готовый wxWidgets и не собирает его. Сначала соберите DLL-конфигурации
`src\3rdparty\wxWidgets\build\msw\wx_vc17.sln`; см.
[Сборка из исходников](../build-from-source/#build-with-visual-studio-windows).

**Release x64: `C1002: compiler is out of heap space in pass 2`.**
32-битному хосту компилятора не хватает памяти на самых больших файлах. Собирайте с
`/p:PreferredToolArchitecture=x64`.

**`C1060: compiler is out of heap space` в случайных файлах, или машина зависает во время
сборки.**
Одновременно работает слишком много компиляторов. С CMake вне пресета используйте `--parallel 3` при
16 ГБ ОЗУ или `--parallel 2` при 8 ГБ (на Linux и macOS пресеты уже ограничивают число заданий).
С MSBuild используйте `/m:1`.

**`fatal: Unable to find current revision in submodule path 'src/3rdparty/wxWidgets'`.**
Прерванная сборка или загрузка оставила подмодуль сломанным.
`rm -rf src/3rdparty/wxWidgets`, затем `git submodule update --init --recursive`.

**`LNK1168: cannot open … for writing`.**
Программа из выходной папки ещё работает и держит свой файл. Закройте `appstudio`,
`appworkspace`, `launcher`, `appcluster` и его процессы `appserver`, затем соберите снова.

**После `git pull` собранное падает при запуске или линкер требует функцию, которой в исходниках
больше нет.**
Объектные файлы старой или прерванной сборки смешались с новыми. Пересоберите начисто:
`/t:Rebuild` в MSBuild, `--clean-first` в CMake.
