Know the books? Change the system yourself.

OpenES is a platform for business applications* — stock, accounting, payroll, sales. An AI assistant connects to it directly: tell it in plain words what to keep and what to see, and it builds the catalogs, the documents, the postings and the reports. No specification for a programmer, and no waiting in their queue.

You check the result the way you always have: a posted document, a trial balance, a printed form.

What it gives each of you

For the owner

  • The whole company in one base: stock, settlements, accounting, payroll — and several companies side by side.
  • The books change as the business does, without a queue for a programmer.
  • The database is on your own server, or right on your own computer; look at it from a browser, on a phone too.

For the accountant

  • Double entry over a chart of accounts with account dimensions; Anglo-Saxon and continental books agree to the cent.
  • Trial balance, general ledger, drill-down to the entry.
  • Payroll: salary, bonus, sick leave, income tax, recalculation of past periods and the payroll sheet.
  • In the workspace the assistant opens a report, finds a document or corrects a value — within your rights.

For the economist and finance

  • Balances and turnovers at any date, FIFO lots and cost; documents repost from the point they need to.
  • Prices and exchange rates at any date.
  • Reports are put together with the mouse: groupings, totals, cross tables, your own saved variants.
  • Export to Excel, Word and PDF, sending by mail.

For implementers

  • A consultant tells the assistant what used to go into a specification for a programmer.
  • A solution is built faster, with less work and fewer mistakes — and at a fixed price, the difference is yours.
  • The mechanisms combine in one base: one goods receipt posts to stock, to lots and to each chart of accounts.
  • HTTP services for exchange with a website and other systems; scheduled and background jobs.

The assistant works in plain sight: the studio shows each step it takes, it describes a change to the database in the books' own words — “the document Order got an attribute” — and every call stays in the journal.

Complex accounting — in one base

Accounting, payroll and stock here are the platform's own mechanisms, not workarounds: accounting, calculation, accumulation and information registers. That is why they combine, and there is no separate product for each task. That sick leave displaces salary, and that salary is the base of a bonus, the calculation register knows itself, not code around it.

A query asks the books in their own words

The query language is half bookkeeping: it has balances and turnovers, receipt and expense, turnovers between accounts, prices at a date and accruals for a period. An accountant reads such a query almost as a sentence, and the platform turns it into SQL for the server itself. The rules — how a document posts, how an accrual is figured — are written in the built-in language in the same words: document, register, balance.

Runs on your own computer

Download the archive for Windows, Linux or macOS and unpack it: the database engine is inside, there is no server to install. Add a folder on disk in the launcher, and the base is ready. A file base is enough to develop in and for a small office; a team takes PostgreSQL and the application server. Installation

Why OpenES is built this way

OpenES is written in C++ as one whole system, from storing the data to the screen. Here is what that gives; under each point, how it is done, for engineers.

One meaning from the database to the screen

A sum in a report is the same sum as in the database: no chain of different programs recalculates or rewrites it on the way, and cents are not lost to rounding. So figures do not drift apart, and the system does not slide from version to version.

For engineers. One core in C++, from storage to the form: a number (exact decimal), a date, a string and a reference mean the same on the server, in the client and in the protocol; a query becomes SQL in the platform, in one place; the client only draws.

Its own where the figures rest

The language, the queries, the calculations and the storage format — everything your data rests on — the platform makes itself. Proven libraries for the network, the windows and PDF it takes ready-made, but keeps inside itself. So in ten years it will start just as it does today.

For engineers. No .NET, Java, Node or Python is needed. The compiler and bytecode, the query engine, the protocol and the storage format are its own; ASIO, Mbed TLS, expat, libharu, lunasvg and its own branch of wxWidgets are submodules in the source tree; the Firebird engine ships in the package.

Runs everywhere

Windows, Linux, macOS — and a browser, a phone's too. One and the same application, without a separate version for each system.

For engineers. One code base builds with MSVC, GCC and Apple Clang (Windows x64, Linux x64, macOS arm64) and passes the same tests; the browser client is the same session on the server.

It is not an end in itself — the class of the task asks for it: accounting has to give the same figures for years, on any machine. Engineers call such a build a vertically integrated stack: from storing the data to the screen, one system, not a set of other people's products stitched together.

For developers

Under the assistant is an ordinary platform in C++20, and whatever it does can be done by hand. You describe the business in metadata, write its rules in a built-in language and read its data with queries and reports. The platform makes the tables, the forms and the reports, and keeps the database in step as the description changes.

What is inside

An assistant at work
A built-in MCP server: an AI assistant reads, builds and checks an application with the rights of the person who let it in, and every call is journalled.
Registers
Information, accumulation, accounting — a chart of accounts and double entry — and calculation for payroll.
Query language
SELECT over business objects and the registers' balances and turnovers. It runs as SQL on the server, or in memory with the same answer.
Report composer
Groupings, totals, cross tables, drill-down to the records, and each user's saved settings. Prints, and exports to Excel and Word.
The language
C-flavoured CES, or keyword-fenced VES: one compiler to bytecode, with lambdas, exceptions and LINQ.
Studio
Metadata tree, form designer, code editor with completion, query constructor, remote debugger and a git panel.
Access rights
Rights per role, and row-level security written as code in the role. It fails closed.
Server and cluster
A server process per base; the cluster restarts one that falls, and the other bases do not notice. Firebird and PostgreSQL.
Browser
The same application in a browser, on a desktop and on a phone. The server holds the session; the client only draws.
